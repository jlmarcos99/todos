# NPM Package and CI/CD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Prepare Todos as the public `@jlmarcos99/todos` package with a `todos` executable and a Changesets release that publishes only after a version change is merged into `master`.

**Architecture:** Keep the existing TypeScript build and binary. GitHub Actions validates the project and an installed npm tarball; Changesets creates version PRs, and a separate `master`-only workflow publishes through npm OIDC.

**Tech Stack:** npm, TypeScript, Node.js, GitHub Actions, Changesets, npm Trusted Publishing.

**Spec:** `docs/superpowers/specs/2026-11-02-npm-cicd-design.md`

## Global Constraints

- Package name: `@jlmarcos99/todos`; executable: `todos`.
- Preserve Node engine requirement `>=22.19.0`.
- Publish only `dist/index.js`, runtime files under `dist/app/src/`, README, and package metadata.
- Only a push to `master` may publish, and only after release validation passes; `develop` remains validated by CI.
- npm CLI in the publishing workflow must be at least `11.5.1`.
- Do not commit, publish, or alter unrelated application changes.
- Reuse tests under `app/tests`; do not add product tests.

## Review Focus

- A scoped package must be public and carry the expected executable after installation; verify tarball metadata and run `todos --help` from a temporary install.
- `dist/index.js` must retain its executable shebang and executable mode in the packed tarball; verify the installed binary runs in CI.
- Tests must not rely on Node's limited direct TypeScript loader; compile them with the existing TypeScript build before executing their JavaScript output.
- A PR or push to `develop` must never invoke npm publish; inspect workflow triggers and permissions.
- A push/merge to `master` must run Changesets, but publish only after a version PR updates package versions; inspect action configuration and workflow event.
- OIDC publication requires a supported npm CLI and `id-token: write`; verify the configured version floor and workflow permission.
